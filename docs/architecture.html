Factory Inventory Management

Architecture overview of the Vue 3 + FastAPI demo application. Generated from the codebase on 2026-11-03.

At a glance

What it is

A single-page dashboard for factory operations: inventory, orders, demand forecasts, backlog, spending and quarterly reports.

Shape

Two processes. A Vite dev server serves the Vue SPA on port 3000. A FastAPI process serves JSON on port 8001. No database and no auth.

Data

Seven JSON files are read once at backend start into Python lists. Every request filters those lists in memory. Nothing persists across restarts.

Tech stack

Frontend client/

  • Vue 3.4 with Composition API
  • Vue Router 4 (history mode, 6 routes)
  • Axios for HTTP
  • Vite 8 dev server and bundler
  • Custom SVG charts, CSS Grid layouts, scoped styles
  • Hand-rolled i18n (en, ja) with locale-driven currency

Backend server/

  • Python 3.11+, managed with uv
  • FastAPI on Uvicorn
  • Pydantic v2 response models
  • CORS middleware open to all origins
  • Single module main.py (about 300 lines)
  • OpenAPI docs at /docs

Tooling tests/, scripts/, .claude/

  • pytest + FastAPI TestClient, 40 backend tests
  • scripts/start.sh and stop.sh launch both servers
  • Claude Code agents, slash commands and a post-tool-use logging hook
  • GitHub and Playwright MCP integrations configured

System architecture

Data flow: a filter change

1
User picks a filter in FilterBar. The four selects (period, warehouse, category, status) are bound to module-level refs in useFilters.js, so the state is a singleton shared by every view.
2
The active view reacts. Each view calls watch() on the filter refs it cares about and re-runs its load function. Dashboard and Orders watch all four. Inventory, Demand and Backlog watch warehouse and category only. Spending watches period only.
3
api.js builds the request. It drops any filter whose value is all, converts the period into a month query param and sends a GET via Axios.
4
FastAPI filters in memory. The route copies the module-level list through apply_filters (warehouse exact match, category and status case-insensitive) and filter_by_month, which accepts 2025-03 or Q1-2025 and substring-matches against order_date.
5
Pydantic validates the response against the route's response_model, then JSON goes back to the browser.
6
Raw data lands in refs, and everything displayed (totals, chart series, low-stock lists) is derived in computed() properties. Currency and labels are translated at render time through useI18n.

Observations worth knowing

Gap Frontend calls endpoints the backend does not have

api.js defines GET/POST/PATCH/DELETE for /api/tasks and POST/GET for /api/purchase-orders. App.vue calls the task methods on mount. main.py has only GET routes and no tasks or purchase-order handlers, although a CreatePurchaseOrderRequest model and the purchase_orders list are already wired. Expect 404s in the console until those routes exist.

Note Backlog view exists but is not routed

views/Backlog.vue is present and uses the filter composable, but main.js registers no /backlog route and the nav has no link. Backlog data is shown inside the Dashboard instead.

Note Filtering is partly server-side, partly client-side

Only inventory, orders and the dashboard summary are filtered by the API. Other views either ignore the global filters or narrow the data in computed properties, so the same filter can mean different things on different pages.

Convention Patterns to follow when extending

  • New endpoint: Pydantic model, route in main.py, test in tests/backend
  • Changing JSON shape: update the matching model or validation fails
  • Views: raw data in refs, derived data in computed, unique v-for keys
  • Validate dates before calling getMonth()
  • Revenue goals: 800K per month, 9.6M year to date
Demo application: in-memory data, no persistence, no authentication, CORS open. Suitable for local development only.
